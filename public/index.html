        Routing
        Chooses the agent, model and effort for each message.
        How routing works
        • It reads your message with simple rules, never a model call, so choosing uses none of your plan.
        • Small edits and quick questions get a light model; focused changes the agent’s standard one; refactoring, debugging, migrations, security, performance and large requests the strongest, with more effort.
        • It keeps the agent from your last run, so the conversation keeps its session, and moves on when that agent nears its limit. It never picks one at 95%.
        • It only picks agents billed to a subscription unless you allow API billing above. Unknown billing is not treated as free.
        • The choice and the reason show above the message box before you send.
        • With Check with tests, a run that changes files is followed by this workspace’s test command, the one marked for it in Run. If the tests fail, Balanced and Maximum quality retry once with the same agent, one step up in model or effort, and tell it what failed. Cost saving, or an agent near its limit, asks first. A retry is never retried, and queued prompts wait until the tests pass.
        
          
        Handoff
        Moves a running task to another connected agent before the current one reaches its plan limit. You see the agent, its billing and the task before it switches.
